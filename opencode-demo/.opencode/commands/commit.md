# Commit 命令

自动审查代码变更并创建 commit：$ARGUMENTS

## 你的任务

1. **代码审查** - 先调用 `/review` 命令
2. **分析变更** - 获取并分析 git 变更内容
3. **生成信息** - 根据变更生成符合项目风格的 commit 信息
4. **执行提交** - 自动执行 git commit

## 执行步骤

### 步骤 1：代码审查

调用代码审查命令：

```
/review
```

**重要**：

- 检查审查结果中的严重性问题
- 如果发现 **关键** 或 **高** 严重性问题，**停止执行** 并要求用户先修复这些问题
- 如果只有 **中** 或 **低** 严重性问题，可以继续

### 步骤 2：获取变更信息

并行运行以下命令获取变更信息：

```bash
git status
git diff --name-status
git diff --stat
git diff --cached --name-status
git diff --cached --stat
git log -5 --oneline
```

**分析要点**：

- 哪些文件被修改/新增/删除
- 变更的行数统计
- 是否有已暂存的变更
- 最近的 commit 风格（用于保持一致性）

### 步骤 3：生成 commit 信息

根据变更内容分析 commit 类型：

| 变更类型 | commit type 前缀 | 说明                           |
| -------- | ---------------- | ------------------------------ |
| 新功能   | `feat:`          | 添加新功能、新组件、新页面     |
| Bug 修复 | `fix:`           | 修复已知问题                   |
| 重构     | `refactor:`      | 代码重构，不影响功能           |
| 文档     | `docs:`          | 仅文档变更                     |
| 样式     | `style:`         | 代码格式调整（空格、格式化等） |
| 测试     | `test:`          | 添加或修改测试                 |
| 构建     | `chore:`         | 构建工具、依赖更新等           |

**Commit 信息格式**：

```
<type>: <简短描述>

<可选的详细描述>
```

**规则**：

- 使用项目现有风格（参考 git log）
- 描述简短（50-80 字符）
- 中文描述（与项目 AGENTS.md 风格一致）
- 第一行简洁，说明"做了什么"和"为什么"
- 如需要详细说明，空一行后添加

**示例**（基于项目历史）：

```
feat: 添加用户登录功能
```

```
fix: 修复导航栏在移动端显示异常的问题
```

```
refactor: 优化组件状态管理逻辑
```

### 步骤 4：执行 commit

**如果有未暂存的变更**：

1. 显示变更的文件列表
2. 显示生成的 commit 信息
3. 执行 `git add .` 暂存所有变更
4. 执行 `git commit -m "<commit 信息>"`

**如果已有暂存的变更**：

1. 显示暂存的文件列表
2. 显示生成的 commit 信息
3. 执行 `git commit -m "<commit 信息>"`

**验证**：
运行 `git status` 确认提交成功

### 步骤 5：提交后检查

提交成功后，执行以下检查：

```bash
git log -1 --stat
```

显示刚创建的 commit 信息和变更统计，确认提交正确。

## 边界情况处理

### 没有变更

如果运行 `git status` 显示没有变更：

```
当前没有需要提交的变更。请先进行代码修改。
```

### 代码审查失败

如果 `/review` 发现关键或高严重性问题：

```
❌ 代码审查发现以下问题，请修复后再提交：

[列出关键和高严重性问题]

修复后请重新运行 /commit 命令。
```

### Commit 失败

如果 git commit 失败：
显示 git 的错误信息，并提示用户可能的解决方案。
